## 3) App relevance

- **h2 buys the app two things, and one premise in the brief is only half right.**
  1. *Per-host connection reuse over ALPN-negotiated h2* — httpcore marks an h2-capable connection
     available for concurrent requests (`httpcore/_async/connection.py:180-186`, `is_available()`
     returns true when `self._http2 and (scheme == b"https" or not self._http1)`), so one TCP+TLS
     handshake serves many requests to the same host.
  2. *True stream multiplexing* — but only when many requests target **one** origin concurrently.
- **The app's own `http_client.py` http2 serves only avatars and the update check**
  (`src/services/cache_service.py:278`, `src/services/update_service.py:72`) — a GitHub config URL and
  a handful of avatar CDNs. Few origins, low volume → multiplexing benefit is negligible; the real
  gain is h2 keepalive on repeat hits to the same CDN.
- **The engine's site checks are the real user of h2**, and they go through
  `src/services/user_scanner_compat.py` → `user_scanner.core.orchestrator.make_request` →
  `get_client` → `httpx.Client(http2=use_http2, ...)`. Since site checks fan out to *many different
  hosts* (one origin each), multiplexing within a single origin is rare; the practical win is again
  per-host h2 keepalive, and only for the 19 sites that opt in. The remaining 52 `make_request` sites
  and the impersonated curl_cffi traffic run HTTP/1.1.
- **Correctness pitfalls, checked against the installed source — all benign:**
  - *HPACK state is strictly per-connection.* `h2/connection.py:330-331` — `H2Connection.__init__`
    creates its own `self.encoder = Encoder()` / `self.decoder = Decoder()`; the dynamic table
    default is 4096 octets (`h2/settings.py:138`,
    `SettingCodes.HEADER_TABLE_SIZE: collections.deque([4096])`). httpcore builds one
    `AsyncHTTP2Connection` per TCP connection (`httpcore/_async/http2.py:55`,
    `self._h2_state = h2.connection.H2Connection(config=self.CONFIG)`) and the pool keys connections by
    origin (`httpcore/_async/connection_pool.py:140,164,173`). Encoder/decoder state therefore always
    matches the wire and can never leak between connections. No HPACK corruption risk.
  - *Connection reuse across proxies is safe.* The app builds a **separate** proxy transport
    (`src/services/http_client.py:60-62`) mounted at `"all://"`, mapped by httpx to
    `httpcore.AsyncHTTPProxy` with `http2=http2` (`httpx/_transports/default.py:312-328`). For
    http/https proxies httpcore uses `AsyncTunnelHTTPConnection` → CONNECT, then TLS with ALPN
    `["http/1.1", "h2"]` **inside** the tunnel
    (`httpcore/_async/http_proxy.py:233-243, 283, 307, 321-328`). SOCKS5 goes through
    `AsyncSOCKSProxy` (`httpcore/_async/socks_proxy.py:105-159`) and the same TLS/ALPN path. Each
    target host gets its own tunnel, its own h2 connection, and its own HPACK context — no state
    crossover between the direct and proxy legs.
  - *h2 is never forced on a server that does not offer it.* ALPN is only set for
    `https`/`wss` origins (`httpcore/_async/connection.py:140-146`); h2 is selected only when
    ALPN negotiates it, otherwise httpcore falls back to HTTP/1.1
    (`httpcore/_async/connection.py:81-86`). Plain `http://` origins simply stay HTTP/1.1.
  - *Memory:* each pooled h2 connection holds one Encoder + Decoder (few KB). With
    `max_keepalive_connections=10` this is negligible.

## 4) Verdict

**KEEP — h2 4.4.1 is a required, working dependency of this venv.**

- Genuinely installed (4.4.1, uv-installed, with `hpack` 4.2.0 + `hyperframe` 6.1.0) and the
  `httpx[http2]` path was **verified live** in this venv: sync/async clients, both transports, and
  the app's exact direct and proxy transport constructions all build and close cleanly with
  `http2=True`.
- The app does not import h2 directly (confirmed by exhaustive grep); it depends on it entirely
  through httpx's `http2=True` flag.
- **h2 is a hard runtime requirement, not an optional extra for this app:** `src/services/http_client.py`
  hard-codes `http2=True` at four sites (`:58, :61, :67, :74`), so removing h2 would break the shared
  client at build time (`httpx/_client.py:1392-1397`) and take out avatar downloads and update checks
  with it. The two engines that declare `httpx[http2]` (`uv.lock:354` phonsint, `uv.lock:535`
  user-scanner) are the lockfile's only route to h2 — but even if both dropped the extra, the app's
  own `http2=True` usage would still need h2 present, so the lockfile declaration should stay
  consistent with the app's real requirement.
- The payoff is modest and narrower than "multiplexing on the engine's site checks": it is mostly
  per-host h2 keepalive (fewer TCP+TLS handshakes) across many distinct hosts, plus multiplexing
  only on the 19 user-scan sites that opt in. phonsint declares the extra but never uses it.
- No correctness defects found: HPACK encoder/decoder state is correctly per-connection, proxy
  tunnels carry their own h2 connection and HPACK context, and non-h2 servers fall back cleanly to
  HTTP/1.1.
